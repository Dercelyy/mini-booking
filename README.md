# Mini Booking

Бронирование одной переговорной комнаты. Laravel 12 JSON API, Vue 3 + TypeScript + PrimeVue 4, PostgreSQL 17. Два независимо собираемых приложения: `backend` владеет данными и бизнес-правилами, `frontend` общается с ним только по HTTP. PostgreSQL доступен внутри Docker-сети. Авторизации, админки, управления комнатами, очередей и cron нет.

## Запуск

Нужны Docker с Compose v2 и Node.js 22.12+ (генерация локального окружения и дополнительные проверки). PHP и Composer на хосте не требуются. Все команды ниже выполняются из корня репозитория.

```sh
node scripts/init-env.mjs
docker compose build
docker compose up -d db
docker compose run --rm api php artisan migrate --seed --force
docker compose up -d --wait api frontend
```

Страница: [http://127.0.0.1:5173](http://127.0.0.1:5173). API: [http://127.0.0.1:8000/api/slots](http://127.0.0.1:8000/api/slots).

`init-env.mjs` создаёт `.env` со случайным паролем PostgreSQL и ключом Laravel, существующий файл сохраняет. Настройки находятся в корневом `.env.example`: `DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD`, `APP_KEY`, `APP_TIMEZONE`, `API_PORT`, `FRONTEND_PORT`. Реальные `.env` в Git не попадают. После изменения настроек контейнеры нужно пересоздать: `docker compose up -d --force-recreate`. Пароль уже инициализированного PostgreSQL сам от смены `.env` не меняется.

API работает на PHP 8.4 с `pdo_pgsql`, `mbstring`, `dom`; зависимости зафиксированы в `composer.lock`. Frontend использует Node 22 при сборке и Nginx для раздачи; зависимости зафиксированы в `package-lock.json`. Nginx проксирует `/api` в backend, поэтому CORS не требуется. PHP development server с четырьмя workers предназначен для локального тестового задания.

Остановка с сохранением базы:

```sh
docker compose down
```

Повторный запуск и добавление недостающих дней:

```sh
docker compose up -d
docker compose exec api php artisan db:seed --force
```

После изменения исходников: `docker compose up -d --build`. База хранится в именованном volume `yan-booking_postgres_data`; обычная пересборка её сохраняет.

## Разработка frontend

При работающем API можно запустить Vite отдельно (сначала остановить контейнер frontend, чтобы освободить порт):

```sh
docker compose stop frontend
cd frontend
npm ci
npm run dev
```

Vite проксирует `/api` на `http://127.0.0.1:8000`. Другой адрес задаётся переменной `API_PROXY_TARGET` в `frontend/.env.local`. Проверка типов и сборка: `npm run build`. Для backend исходники запекаются в образ; после правок пересобрать `api`.

## API

Все API-ответы, включая ошибки, возвращаются в JSON. Для запросов рекомендуется заголовок `Accept: application/json`.

| Запрос | Результат |
| --- | --- |
| `GET /api/slots` | `200 {data: [...], timezone, server_time}`; сортировка по началу |
| `POST /api/bookings` | `201 {id}`; поля `slot_id`, `customer_name`, `customer_email` |
| `DELETE /api/bookings/{id}` | `204`; повторная отмена существующей записи тоже `204`, неизвестный ID `404` |

Слот содержит `id`, `starts_at`, `ends_at`, `status` (`available`, `booked`, `past`), `booking_id` (число или `null`). Имя и email не включаются. При прошедшем слоте статус всегда `past`, но ID активного бронирования сохраняется и отмена доступна.

Laravel FormRequest проверяет обязательность полей, существование слота, email, длину имени до 150 и email до 254 символов. Ошибки полей: `422 {message, errors}`. Занятый или уже начавшийся слот: `409 {message}`. Неизвестное бронирование: `404`.

Отмена по известному ID доступна без авторизации строго по условиям демо. Клиент показывает подтверждение отмены, состояния загрузки и ошибки, обновляет расписание после изменения и конфликта. При сетевой или серверной ошибке действие можно повторить; после ошибки обновления списка отдельно повторяется загрузка.

## Целостность и время

Создание бронирования проходит в транзакции с `SELECT FOR UPDATE` на строке слота. После получения блокировки повторно проверяются время и активная бронь. Это сериализует конкурирующие запросы к одному слоту. Дополнительно PostgreSQL partial unique index `bookings_active_slot_unique` запрещает две строки с одинаковым `slot_id` и `cancelled_at IS NULL`, в том числе при записи в обход контроллера. Нарушение уникальности преобразуется в `409`. Отмена устанавливает `cancelled_at`, история остаётся, индекс допускает новую бронь.

`APP_TIMEZONE` задаёт часовой пояс Laravel и расписания, по умолчанию `Asia/Krasnoyarsk`. Seeder создаёт сегодня и следующие шесть календарных дней, ежедневно девять часовых слотов с 09:00 до 18:00, включая прошедшие часы и выходные. Настройки расписания вынесены в `backend/config/booking.php`. Уникальный `starts_at` и `insertOrIgnore` сохраняют существующие слоты и бронирования, добавляя недостающие дни.

PostgreSQL хранит моменты в `timestamptz`; записи моделей и Seeder передают явное UTC-смещение. API возвращает ISO 8601 со смещением часового пояса расписания. `starts_at <= now()` означает прошедший слот. Frontend форматирует даты через `Intl.DateTimeFormat` с часовым поясом из API; локальный часовой пояс браузера не влияет. Между загрузками время клиента корректируется по `server_time`, статус обновляется ежесекундно; окончательное решение всегда принимает backend.

## Проверки

```sh
docker compose exec api php artisan test
docker compose exec api vendor/bin/pint --test
node scripts/check-concurrency.mjs
cd frontend
npm ci
npm run build
```

PHPUnit использует отдельную базу `booking_test`, которую создаёт `docker/init-test.sql` при первой инициализации volume. Имя тестовой базы принудительно задано в `tests/TestCase.php`, чтобы переменные контейнера не направили `RefreshDatabase` в базу демо. Для volume, созданного без init-скрипта, один раз выполнить `docker compose exec db psql -U booking -d booking -c 'CREATE DATABASE booking_test'` (подставить свои имя пользователя и базы при изменении настроек).

Тесты проверяют успешную бронь, повторный запрос с `409` без второй записи, отмену и повторную бронь, точную границу начала слота, валидацию, отсутствие персональных данных в списке, повторный Seeder и переход на следующий день. Скрипт конкуренции отправляет десять одновременных запросов к свободному будущему слоту локального API, ожидает один `201` и девять `409`, затем отменяет созданную бронь. Запускать его только на локальном демо.

Проверено 17 ноября 2026 года: Docker-сборка обеих частей, 7 тестов PHPUnit (34 проверки), Laravel Pint, TypeScript и Vite build. Десять одновременных HTTP-запросов дали один `201` и девять `409`. В браузере проверены создание и отмена, обязательные поля, ошибки `422` и `409` с обновлением списка, сетевой сбой и успешный повтор, фильтр дат и прошедшие слоты. Адаптивность и computed styles проверены на 390, 700, 701 и 1280 px; горизонтального переполнения нет. После проверок в базе демо 63 слота и ни одного активного тестового бронирования.
